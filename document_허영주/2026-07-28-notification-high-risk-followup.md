# 프로젝트 알림 고위험 피드백 후속 조치

## 변경 사항

- `project_members` 기반 과거 알림 프로젝트 역산을 제거했다. 프로젝트 탈퇴 이력이 보존되지 않으므로 현재 또는 특정 시점의 소속 수만으로 과거 프로젝트를 확정할 수 없기 때문이다.
- `target_type='project'`이고 `target_id`가 존재하는 것처럼 원본 대상으로 프로젝트를 확정할 수 있는 경우만 백필한다.
- 프론트 업무보드에서 동일 업무의 상태 이동 요청이 진행 중이면 후속 이동 요청을 보내지 않는다.
- 백엔드는 상태 이동 조회에 비관적 쓰기 잠금을 사용한다. 같은 업무에 대한 동시 요청은 직렬화되며, 후속 요청은 이미 변경된 상태를 읽으므로 상태 변경 알림을 다시 만들지 않는다.

## 프로젝트별 스코핑 diff 설명

프로젝트별 조회, 미읽음 집계, SSE 현재 프로젝트 필터링은 최신 `dev`에 이미 존재한다. `feature/kanban`을 `dev`와 병합한 뒤의 비교 diff에서는 공통 조상에 포함된 이 코드가 표시되지 않는 것이 정상이며, 최종 병합 트리에는 유지된다.

## 기존 NULL 알림 정책

프로젝트를 확정할 근거가 없는 과거 알림은 데이터베이스에 `NULL`로 보존하되 프로젝트별 화면에는 노출하지 않는다. 잘못된 프로젝트에 귀속해 정보를 노출하는 것보다 보수적인 격리를 우선한다.
