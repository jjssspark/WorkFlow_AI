# 프로젝트별 알림 병합 충돌 및 위험 보완

## 병합 충돌

`feature/kanban`에 최신 `origin/dev`를 병합했다. 알림 서비스의 프로젝트 ID 인자 순서와 프로젝트 컨텍스트 초기화 방식이 양쪽에서 동시에 변경되어 발생한 충돌은 최신 `dev` 구현을 기준으로 해소하고, 업무 딥링크와 팀장용 상태 변경자 문구를 유지했다.

## 보완 사항

- 알림 보관 한도는 사용자 전체 20건이 아니라 사용자·프로젝트별 20건으로 적용한다.
- 진행률 보고서 알림 API는 `@PreAuthorize("@projectAccess.isMember(#request.projectId())")`로 로그인 사용자의 프로젝트 소속을 검증한 뒤 저장한다.
- 중복된 Flyway `V20260728_1` 파일을 하나로 정리했다.
- 추가 마이그레이션에서 다음 경우의 기존 `NULL project_id`를 안전하게 복원한다.
  - `target_type='project'`이고 `target_id`가 있는 경우
  - 알림 생성 당시 사용자가 가입한 프로젝트가 정확히 하나였던 경우
  - 현재 사용자의 소속 프로젝트가 정확히 하나인 경우
- 여러 프로젝트 중 어느 프로젝트인지 결정할 근거가 없는 과거 알림은 오귀속하지 않고 `NULL`로 보존한다.

## 호환성 판단

프로젝트를 확정할 수 없는 기존 알림을 임의의 프로젝트에 표시하면 프로젝트 격리를 훼손한다. 따라서 확정 가능한 데이터만 복원하고, 나머지는 데이터베이스에 보존하되 프로젝트별 화면에서는 제외하는 정책을 적용했다.
