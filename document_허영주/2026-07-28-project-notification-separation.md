# 프로젝트별 알림 분리 구현 결과

## 변경 결과

- `notifications.project_id` 컬럼과 사용자·프로젝트·생성시각 복합 인덱스를 추가했다.
- 기존 업무·회의·마일스톤·평가 알림은 마이그레이션에서 가능한 범위까지 프로젝트 ID를 역산한다.
- 업무보드, 댓글, 마일스톤, 회의, 평가, 진행률 보고서 알림 생성 시 프로젝트 ID를 저장한다.
- 알림 목록과 미확인 개수 API는 `projectId`가 전달되면 해당 프로젝트 알림만 반환한다.
- 프론트엔드는 현재 프로젝트 ID로 목록과 배지를 조회하고, 다른 프로젝트의 SSE 알림은 표시하지 않는다.

## 검증

- 백엔드 알림 테스트 통과
- 업무보드 알림 관련 백엔드 테스트 74개 통과
- 프론트엔드 알림 테스트 22개 통과
- 프론트엔드 프로덕션 빌드 통과
- 전체 백엔드 회귀 실행에서는 Windows의 심볼릭 링크 생성 권한이 없어 기존 보안 테스트 1개만 실패했다.

## 업무 알림 딥링크

- 종 아이콘 알림 목록과 실시간 토스트의 업무 알림에 `바로가기`를 추가했다.
- 클릭 시 `/board?taskId={업무ID}`로 이동하고 업무 목록 로드 후 상세 패널을 자동으로 연다.
- 기존 담당자·우선순위·카테고리 필터는 초기화해 대상 업무 카드가 숨지 않도록 했다.
- 대상 업무가 삭제되었거나 현재 프로젝트에 없으면 안내 토스트를 표시한다.
- 관련 프론트엔드 테스트 24개와 프로덕션 빌드가 통과했다.
- 최초 진입뿐 아니라 업무보드가 이미 열린 상태에서 알림을 누르는 경우도 URL 검색 파라미터 변경을 감지하도록 수정했다.

## 팀장용 업무 상태 변경 알림

- 팀원이 업무 상태를 변경하면 팀장 알림 본문에 행위자 이름을 포함한다.
- 문구 형식: `김민준님이 '로그인 API' 업무를 '진행 중' 상태로 변경했습니다.`
- 담당자에게 전달되는 기존 상태 변경 알림 문구는 유지한다.
- `TaskControllerPositionTest`로 팀장 수신자와 문구를 검증했다.
