# 업무 상태 알림 중복 및 구문 미반영 진단

## 결론

알림 목록의 중복은 화면이 같은 알림을 두 번 렌더링한 문제가 아니라, 같은 업무의 상태 변경 API가 같은 시각에 두 번 성공하여 백엔드에 알림이 두 건 저장된 결과다.

변경한 알림 구문이 표시되지 않은 이유는 실행 중인 Spring 백엔드 이미지가 해당 코드 변경 전에 만들어진 이미지이기 때문이다.

## 근거

- nginx 접근 로그에서 2026-07-28 11:25:37(KST)에 아래 요청이 두 번 기록되었으며 모두 HTTP 200으로 처리됐다.
  - `PATCH /api/v1/projects/20/tasks/348/position`
- 해당 요청 직전 체크리스트 497, 498의 상태 변경이 연속으로 처리됐다.
- `TaskDetailPanel`의 체크리스트 완료 처리에서는 담당자가 `todo` 상태의 업무를 체크하면 `진행 중으로 이동`을 자동 호출한다.
- 첫 번째 이동 요청이 화면 상태에 반영되기 전에 다음 체크 처리도 이전 `todo` 상태를 참조해 같은 이동 요청을 다시 보낼 수 있다.
- 실행 중인 `app-backend-spring` 이미지는 2026-07-28 10:36(KST)에 생성되었다. 담당자 이름을 포함하도록 변경한 알림 코드는 그 이후 작업이므로 현재 컨테이너에 포함되지 않았다.

## 권장 수정

1. 프론트엔드에서 업무별 상태 이동 요청을 한 번만 수행하도록 in-flight 가드를 둔다.
2. 백엔드에서도 동시 요청이 같은 이전 상태를 읽더라도 알림이 중복 생성되지 않도록 잠금 또는 멱등성 검사를 추가한다.
3. 수정된 알림 구문을 반영하려면 Spring 백엔드 이미지를 다시 빌드해 컨테이너를 재기동한다.

기존에 이미 저장된 중복 알림은 새 코드 배포만으로 자동 삭제되지 않는다.
